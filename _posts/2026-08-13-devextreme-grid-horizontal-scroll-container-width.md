## 문제 상황

Vue와 DevExtreme DataGrid로 구성한 분할 화면에서 왼쪽 목록 영역에 불필요한 가로 스크롤이 나타났다. 표시하는 컬럼은 체크박스, 날짜, 토글처럼 소수였고 값도 짧았지만, 사용자는 목록의 오른쪽 끝을 보기 위해 가로로 스크롤해야 했다.

처음에는 DataGrid의 컬럼 자동 너비나 스크롤 옵션을 의심하기 쉽다. 하지만 이 경우에는 컬럼 설정이 아니라 그리드를 감싼 패널의 고정 너비가 실제 콘텐츠 너비보다 작다는 점이 핵심이었다.

## 원인

### 컬럼 너비의 합과 컨테이너 너비가 맞지 않았다

그리드가 필요로 하는 폭은 눈에 보이는 데이터 컬럼의 너비만으로 결정되지 않는다. 다음 요소도 함께 차지하는 공간에 포함된다.

- 행 선택용 체크박스 컬럼
- 데이터 컬럼과 토글 컬럼
- 셀 좌우 여백과 경계선
- 그리드 내부 스크롤 영역의 보정 폭

반면 왼쪽 패널은 Flexbox 레이아웃에서 고정 폭으로 설정되어 있었다. 패널이 줄어들지 않도록 `flex-shrink: 0`도 적용되어 있어, 그리드는 부모 영역 안에서 컬럼을 모두 표시하지 못하고 가로 스크롤을 생성했다.

```css
.split-layout {
  display: flex;
  gap: 1rem;
}

.list-panel {
  width: 14rem;
  flex: none;
}
```

이 구조에서는 DataGrid의 너비가 `100%`여도 부모 패널보다 넓어질 수 없다. 즉 자식 그리드의 옵션을 바꿔도 부모가 제공하는 공간이 부족하면 스크롤 문제는 남는다.

### 가로 스크롤은 증상이고 고정 폭 불일치가 원인이었다

가로 스크롤을 CSS로 숨기면 당장은 화면이 깔끔해 보일 수 있지만, 오른쪽 컬럼이나 토글이 잘려 조작할 수 없게 된다. 컬럼 너비를 무리하게 줄이는 방법도 헤더와 값의 가독성을 떨어뜨린다.

따라서 먼저 브라우저 개발자 도구에서 다음 값을 비교하는 것이 중요하다.

1. 패널의 실제 렌더링 너비
2. DataGrid 내부 테이블의 스크롤 너비
3. 선택 컬럼과 각 데이터 컬럼이 차지하는 총 너비

`scrollWidth`가 `clientWidth`보다 크고 그 차이가 작다면, 스크롤 기능보다 컨테이너 크기를 우선 점검할 수 있다.

## 해결 방법

왼쪽 패널이 그리드의 전체 컬럼을 수용하도록 고정 폭을 필요한 만큼 늘렸다. 오른쪽 상세 영역과의 분할 구조 및 `flex: none` 동작은 그대로 유지했다.

```css
.list-panel {
  /* 체크박스, 날짜, 토글 컬럼과 셀 여백을 모두 수용한다. */
  width: 16rem;
  flex: none;
}
```

변경 범위는 부모 컨테이너의 너비 한 곳으로 제한했다. DataGrid의 컬럼 정의, 조회 로직, 선택 이벤트, 스크롤 설정은 수정하지 않았다.

레이아웃 수정 시에는 단순히 스크롤이 사라졌는지만 확인하지 않고 다음 항목도 함께 점검해야 한다.

- 마지막 컬럼과 토글이 잘리지 않는지
- 왼쪽 패널을 넓힌 뒤 오른쪽 상세 영역이 정상적으로 줄어드는지
- 작은 화면에서 전체 페이지에 새로운 가로 스크롤이 생기지 않는지
- 헤더와 본문의 컬럼 정렬이 일치하는지

## 결과

- 왼쪽 DataGrid에서 불필요한 가로 스크롤이 사라졌다.
- 날짜와 토글 컬럼을 한 화면에서 모두 확인하고 조작할 수 있게 됐다.
- 데이터 조회와 이벤트 처리 로직에는 영향이 없었다.
- 한 곳의 컨테이너 너비만 조정해 변경 범위를 최소화했다.

분할 레이아웃 안의 DataGrid에 가로 스크롤이 생겼다면 그리드 옵션부터 바꾸기 전에 부모 컨테이너가 실제 컬럼 너비를 수용하는지 확인하는 것이 좋다. 특히 선택 컬럼, 셀 여백, 경계선처럼 눈에 잘 띄지 않는 폭까지 합산해야 정확한 원인을 찾을 수 있다.
